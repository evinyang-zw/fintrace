## 0. 结论（先看这五条）

- **70 题金标 = 60 开发 + 10 holdout**（6 类，每类 ≥8）。开发集 4 个 seed 合并（n=240）：答案正确率 **99.0%**，95% CI `[97.6, 100.0]`；同题 50 题子集 **98.9%**，与 W4 的 95.0% 同题可对照。
- **holdout 一次性结果：95.0%**（10 题 × 2 seed，n=20，CI `[85.0, 100.0]`）。**10 题里 9 题两次都对；唯一失败是 AMZN 分部表的一题在被拒答一次**——holdout 的作用不是给一个漂亮数字，是给一个没说谎的数字。
- **引用语义支撑率 98.4%**（开发集）、91.8%（holdout）。数字引 XBRL 事实做确定性复算，正文引 claim 级 entailment；判官 60 条盲标 κ **0.795**，引用 checker 30 条盲标 κ **0.634**。
- **拒答**：8 道不可答题 4 seed 全部正确拒答（召回 100%）；开发集误拒率 **0%**。
- **成本 / 延迟**：开发集单题 **$0.00059**（LLM $0.00059 + 检索 $0.0000012），p50/p95 **4.96s / 12.58s**；线上 30 天均值 $0.00129/题（多跳题更贵）。

## 2. 数据集

|---|---|---|---|---|
| F1 事实 | 10（含 5 道引用陷阱） | 0 | 检索命中与引用精度 | 数值/关键点 + 引用结构 |
| F2 多跳 | 20 | **5** | 跨文档、跨章节串联 | LLM 判官（rubric） |
| C1 计算 | 8 | 0 | 抽取 + 运算 + 单位 | 与 XBRL 精确比对 |
| C2 对比 | 16 | **5** | 多实体对齐 | 数值 + LLM 判官 |
| A1 对抗 | 8 | 0 | 注入 / 单位 / 时点 / 实体混淆 | 规则 + 判官 |
| R1 不可答 | 8 | 0 | 拒答校准 | 规则 |

- **为什么不是 100 题**：主设计原计划 100（含 20 holdout）。W6 按时间账把它收在 70——再出 50 题约需 6–7h，会挤掉视频与文章。设计 §9.2 本就留了"60 题也接受"的退路；W6 在此基础上多做 10 道 holdout，全部放在 W4 唯一会掉分的 F2/C2（C1/A1/R1 已接近满分，拿它们做 holdout 只会重复测量 100%）。
- 语料：10 家美股公司、233 份 10-K/10-Q、85,079 条 XBRL 事实，外加 5 份合成对抗文档。
- 每题带 `as_of`（point-in-time 过滤）、`required_citations`、`key_points`、rubric；数值题的 gold 由 `q-check` 从 XBRL 逐条复算。

## 4. holdout 结果（一次性）

### 4.1 先说一次作废的 run

第一次 holdout（tag `v1.0-final`）跑出来：正确率 **100%**，但数值准确率只有 **40%**。
查下去发现**不是模型的问题，是尺子的问题**：三道 C2 的答案 0.63 / 0.39 / 0.25 都是题目要求的两位小数，
但判分器的相对容差 0.5% 把它们判错了（0.25 相对 0.25357 差 1.4%）。

修的是判分器（按题目要求的小数位给绝对容差），agent 代码一行未动（`v1.0-final` → `v1.0.1` 的 diff 只有
`eval/graders.py` 与测试）。按事先的纪律，**第一次 holdout 作废**，修复后重跑一次，下面才是官方结果。

## 6. 限制（必须和结论一起读）

1. **holdout 只有 10 题**，只能看方向，给不出稳定区间；CI `[85, 100]` 本身就是"样本太小"的诚实表达。
2. **开发集 99% 不能当"真实准确率"**。60 道题、6 类，且我们看过这 60 题——它是开发集，不是分布外测试。
3. **判官不是神。** κ=0.795 表示"和人判得一致"，不表示题目没有歧义；`c2-004` 就是反例。
4. **引用 checker κ=0.634**，误差集中在 `partial` 边界；引用分适合看趋势，不适合当精确测量。
5. **表格仍是弱点**：holdout 唯一失败是 AMZN 分部表；W4 的 C2 掉分也集中在表格式口径。
6. **线上评测不是全量**：线上只做 smoke 与并发压测，70 题评测在本地跑；线上 30 天 64 次运行是真实流量样本，不是评测集。
7. **成本口径**：开发集 $0.00059/题是本地跑的价格；线上 7 日均值 $0.00129 更高，因为真实问题更长、多跳更多。
8. **p95 由 provider 抖动主导**，12–14s 的差别可能来自网络，不是代码。

## 7. 复现

```bash
make up                     # Postgres + pgvector
make ingest                 # 10 家公司 / 233 份 filing（首次约 10 分钟）
make embed                  # 20k chunk 向量（需要 DASHSCOPE_API_KEY）
make q-check                # 70 题数据校验（schema + XBRL 对账 + 引用存在性）

# 开发集：60 题 × 4 seed（LLM 判官，hybrid 检索，9 步）
for s in 0 1 2 3; do
  AGENT_MAX_STEPS=9 RETRIEVAL_TIER=hybrid \
    uv run python -m eval.runner --agent graph --judge llm \
    --dataset eval/datasets/gold_v3.jsonl --exclude-tags holdout \
    --seed $s --judge-kappa 0.795 --out reports/w6-dev2/seed$s
done

# holdout：只跑一次（2 seed 算一轮）
for s in 0 1; do
  AGENT_MAX_STEPS=9 RETRIEVAL_TIER=hybrid \
    uv run python -m eval.runner --agent graph --judge llm \
    --dataset eval/datasets/gold_v3.jsonl --tags holdout \
    --seed $s --judge-kappa 0.795 --out reports/w6-holdout2/seed$s
done

# 合并 4 seed / holdout，生成上面这些表
PYTHONPATH=. uv run python scripts/w6_summary.py \
  --dev 'reports/w6-dev2/seed*/2026-*-graph*.json' \
  --holdout 'reports/w6-holdout2/seed*/2026-*-graph*.json' \
  --out reports/w6-final/summary.json
```
