# W6 演示视频脚本（5 分钟）

> 目标：让一个不熟悉项目的人在 5 分钟内知道"这是什么、凭什么可信、做到什么程度"。
> 录制要求：1080p 屏幕录制 + 中文旁白，不配乐；关键数字烧字幕；**不出现 API key、`.env`、SSH 信息**。
> 线上地址可以出现；Demo 口令输入框出现时打码或用占位符。

## 分镜与旁白

### 0:00–0:25 三个坑

**画面**：黑底白字三行，逐行出现；右下角小字 "FinTrace"。

> 旁白：
> "财报问答有三个坑：数字读错单位、引用了一段其实不支撑的段落、以及——明明财报里没有，它却编一个给你。
> 这个项目叫 FinTrace，我用六周时间，专门对着这三个坑做工程。"

### 0:25–1:40 现场演示

**画面**：浏览器打开 `http://47.96.253.123`，输入口令（打码），提一个真实问题：
"苹果 FY2024 的总净营收是多少美元？"
展示 SSE 步骤条（检索 → 取数 → 校验）、答案、点 `[F1]` 展开 XBRL 事实、点"查看 trace"。
再提一个多跳问题："微软 FY2024 的 Microsoft Cloud 收入和增速是多少？"
最后演示一次带 `--review` 的待审流程（可以用预录的 trace 页，避免等待）。

> 旁白：
> "它不是一个聊天框。每一句话带字符级引用，每一个数字可以点开看到它来自哪条 XBRL 事实。
> 这是运行轨迹：先查结构化数据，再决定要不要读原文，最后过一遍校验器。
> 证据不够的时候，它会拒答，并告诉你缺什么。"

### 1:40–2:40 架构

**画面**：README 里的架构图，逐层高亮（浏览器 → FastAPI/队列 → LangGraph → MCP → Postgres）。

> 旁白：
> "四层。第一层数据：10 家公司、233 份财报、8.5 万条 XBRL 事实，入库时带 filed_at，保证时点正确。
> 第二层检索：BM25 + 多语 embedding + RRF，缺 key 会显式降级。
> 第三层是 LangGraph 状态机：agent 和 tools 是循环，外面套 verify → repair → review。
> 第四层是工具边界：4 个只读工具跑在独立进程里，通过 MCP 调用，服务端无状态。
> 关键设计只有一句：**数字不经过大模型**。"

### 2:40–3:50 证据

**画面**：评测报告表格（README 结果表），高亮 60+10、κ、CI；
切到 GitHub PR 的门禁评论截图；再切到 holdout 失败那一行（h-f2-004）。

> 旁白：
> "评测集 70 题：60 道开发集，加 10 道最后才写的 holdout。
> 开发集四个种子，正确率 99.0%，引用支撑 98.4%，误拒 0%。
> holdout 只跑一次，95%——10 题里 9 题两次都对，唯一失败是一次拒答，在亚马逊分部表那题。
> 这个数字我特意没有藏：表格类多跳仍然是弱点。
> 判官也不是随便信的：60 条盲标、加权 κ 0.795；引用校验器 30 条，κ 0.634。
> 第一次 holdout 还抓到我们自己的判分器 bug——0.25 倍这种两位小数被 0.5% 容差误判。修的是尺子，不是模型，作废重跑，写进报告。"

### 3:50–4:40 生产

**画面**：`/dashboard`（请求量、成本、p95）；`/api/health`；`docs/runbook.md` 目录；20 并发压测 JSON。

> 旁白：
> "它现在真的在线：阿里云 2C4G、Docker Compose、FastAPI 服务化、SSE 流式、人工待审。
> 20 并发：20 个全成功，0 个 5xx，p95 28.6 秒。
> 每个 PR 有评测机器人评论：引用支撑掉 2 个点、误拒涨 5 个点就阻断。
> 成本可查：开发集每题 0.0006 美元，线上真实流量均值 0.0013 美元。
> 出事有 runbook：回滚、密钥轮换、数据库恢复，都演练过。"

### 4:40–5:00 限制与下一步

**画面**：回到 README 限制段；最后定帧项目名 + GitHub 地址。

> 旁白：
> "它也有明确的边界：单实例、没上 HTTPS、holdout 只有 10 题、表格还是弱项。
> 下一步我会把题量做到 100、把门禁扩到全量、把实例换成可横向扩展的队列。
> 代码、报告、失败案例都在 GitHub 上，欢迎直接翻。"

## 拍摄清单

- [ ] 浏览器提前登录，问题预先输入好（录制时直接回车，避免拼写错误）
- [ ] 终端字号 ≥ 16pt；关闭通知；隐藏书签栏
- [ ] 录屏工具：QuickTime（屏幕录制）或 OBS；1080p 30fps
- [ ] 旁白分段录，按分镜拼；每段重录不超过 3 次
- [ ] 成片控制在 4:50–5:10；导出 H.264，≤200MB
- [ ] 上传后把链接填进 README 的"5 分钟演示"一行

## 备用方案（演示翻车时）

线上服务可能被限流或 provider 抖动。录制前先跑一遍：
`curl -s http://47.96.253.123/api/health` 四项全 true 再开录。
如果现场失败，切到预录的 trace 页继续讲，不剪辑掩盖——**能讲清楚失败也是加分项**。
