# 简历 bullet（W6 终版）

> 数字来自 W6 终版评测（tag `v1.0.1`）与线上 30 天运行；每条都能指向仓库里的报告、代码或运行记录。

- **从零构建可审计的美股财报 Agent（独立完成，6 周 / 约 120h）**：10 家公司、233 份 10-K/10-Q、85,079 条 XBRL 事实；70 题金标（6 类）+ 自建评测协议、判官校准与 CI 门禁。中文提问 → 检索/计算/交叉验证 → 逐句带引用、数字可复算；证据不足时明确拒答。

- **评测先行，先证明尺子有效再写 Agent**：NullAgent 反验（0% 正确、100% 误拒）；判官 60 条盲标校准，加权 κ 0.603 → **0.795**；引用校验器 30 条盲标 κ 0.634。终版 60 道开发集 × 4 seed **99.0%**（95% CI [97.6, 100]），10 道一次性 holdout **95.0%**；引用语义支撑 **98.4%**、误拒 **0%**。

- **用 trace 定位真瓶颈（不是调参）**：多跳 recall@8 从 80% 提到 100% 后端到端不动——trace 显示 Agent 只读 400 字摘要就拒答。改为聚焦摘要 + 强制读章节后，F2 多跳约 50% → 100%，总体 77.5% → 95.0%（+17.5pt，CI [+5.0, +32.5]）。

- **claim 级引用校验：让"有引用"变成"有证据"**：数字引 XBRL fact 做确定性复算，正文引 LLM entailment；结构口径 92% 的引用在语义口径下只有 56.1%，校验后做到 95–96.4%，并如实报告 checker κ=0.634 只支持相对趋势。

- **手写 ReAct → LangGraph 状态机（A/B 证明不退化）**：50 题 × 4 seed 打平（95.0% vs 95.0%，CI [−3.3, +3.9]）；换来 Postgres checkpoint 跨进程恢复、人工中断放行、生成时 verify/repair（引用支撑 +3.5pt）。工具层 MCP 化：4 个只读工具独立进程，12 条契约测试 + 逐字节接口等价测试。

- **服务化与生产化**：FastAPI + 队列 + SSE + 人工待审，Docker Compose 三容器（db + app + mcp）部署到阿里云 2C4G；**20 并发 20/20 成功、0 个 5xx**，端到端 p95 ≈27s，队列等待 p95 16.2s；镜像 814MB → **302MB**；CI 评测门禁（10 题 replay、无网络）在真实 PR 上发评论，引用 −2pt / 误拒 +5pt 阻断；runbook + 四项故障演练（重启 / MCP 宕机 / 回滚 / 预算熔断）。

- **非确定性系统的工程化**：**210 tests**、覆盖率 76%、mypy strict、CI 不联网（LLM cassette 回放）；定位双峰尾延迟（少数调用卡 15–19s），连接池 + 对冲把 bench p50 从 10.01s 压到 1.0s；单题成本 $0.0006（本地）/ $0.0013（线上真实流量）。

## 面试时的四个追问

- **为什么数字不经过 LLM？** XBRL 是权威来源；模型只选事实和措辞，verify 拿 `[F#]` 与 fact 值做 0.5% 相对误差比对。
- **判官凭什么可信？** 60 条盲标、人标不动只改 rubric，κ 0.603→0.795；残余分歧逐条留档，不为它们继续调 prompt。
- **检索消融为什么"没赢"？** recall 已饱和；三档差异在噪声内。真正的杠杆是工具使用策略（读全文而不是摘要）。
- **holdout 为什么只有 10 题？** 时间账：扩到 100 题会挤掉视频与文章；设计文档允许 60 题底线，70 = 60 开发 + 10 holdout，holdout 只跑一次，第一次跑出的异常是判分器 bug 而非模型问题。
