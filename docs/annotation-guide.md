# 判官校准标注指南（60 条盲标）

目标：用 60 条人工标签检验 `llm-v1` 判官是否可信，报**二次加权 κ**；κ ≥ 0.6 才允许
把它的分数当结论。

## 文件

```bash
uv run python scripts/annotation_pack.py   # 生成 data/annotation/labels.csv（60 行）
```

`data/` 在 `.gitignore` 里，**标签不会进仓库**，可以放心写。

列说明：

| 列 | 含义 |
|---|---|
| `sample_id` | S001–S060，标注时引用这个编号 |
| `question_id` | 对应 `eval/datasets/gold_v1.jsonl` |
| `question` / `key_points` / `gold` | 判分依据，先读这三列 |
| `answer` | 被标注的答案（原样，别改） |
| `label` | **你填 0 / 1 / 2** |
| `reason` | 一句话理由（分歧时尤其重要） |

## 评分标准

| 分 | 含义 |
|---|---|
| **2** | 结论正确，关键要点齐全，没有错误断言 |
| **1** | 结论正确但要点不全，或有一处非致命错误（漏单位、期间口径不清、只答一半） |
| **0** | 结论错误、关键数字错误、答非所问，或对可答题拒答 |

规则：

- 不因措辞、格式、`[K1]` 引用样式扣分（引用由另一个组件评）。
- 数字按数值判断，允许四舍五入；**单位错（百万/十亿）算 0**。
- 数字对但结论与数字矛盾（说"增长"实际下降）算 0。
- 拿不准 1 还是 2 时，给 1，并在 `reason` 写清缺什么。

## 怎么标才不算作弊

1. **不要先跑 `scripts/kappa.py` 看机器分**——看过就会锚定，κ 会虚高。
2. 不要改 `answer` 列去"修好"答案。
3. 标完之前不要改 rubric；rubric 的问题应该在标完后按分歧案例统一修订。
4. 一行大约 2–3 分钟，60 行约 2.5 小时；建议分两次，中间不回头看已标行。

## 算 κ

```bash
uv run python scripts/kappa.py            # 读 data/annotation/labels.csv
```

输出：样本量、完全一致率、二次加权 κ、人工/机器分布、前 10 条分歧。

- κ ≥ 0.6：判官可用，把 κ 写进 W3 报告与后续所有对比。
- κ < 0.6：按分歧案例改 rubric（`eval/llm_judge.py` 的 `_SYSTEM`），**提升 `RUBRIC_VERSION`**，
  重跑判官（人标不动），最多两轮；仍不达标就承认判官不可用，F2 继续标"未计分"。
