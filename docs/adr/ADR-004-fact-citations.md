# ADR-004：数字引用 fact，正文引用 span

- 状态：已接受（W3）
- 日期：2026-10-30

## 背景

W2 的引用只有一种：`(accession, item, char_start, char_end)`。数字来自 XBRL，但为了让引用
"看起来有出处"，`xbrl_fact` 顺手返回了一个指向 Item 8 开头的 4000 字符句柄。

W3 的 claim 级校验器一上线就抓到了这个问题：f1-001 的答案引用 Item 8 的目录页，
`391,035` 确实在该 section 里（第 1425 个字符），但那段文字是"Consolidated Statements of
Operations … Page 29"，并不支撑"总净营收 3910 亿美元"这句话。结构校验 100%，语义校验 0%。

## 决策

1. `xbrl_fact` 的每个候选返回一个 `F#` 句柄，绑定 `(ticker, tag, value, unit, period_end)`。
2. 答案里的数字必须引用 `[F#]`；叙述与定性事实引用 `[K#]`。
3. `Answer` 增加 `facts` 列表；`citation-llm` 对 `[F#]` 走**确定性数值比对**（相对误差 ≤0.5%），
   不调 LLM。
4. 删除"为数字伪造一个正文句柄"的旧逻辑。

## 理由

**数字的出处是 fact，不是段落。** 问"营收是多少"，权威答案是 XBRL 里的那条 fact；引用一段
包含同样数字的 MD&A 只是"文本里也提到了"，不是同一件事。混在一起，判分器无法区分
"数字对且出处对"和"数字对但出处是目录页"。

**确定性校验比 LLM 更便宜也更硬。** 一个数字是否等于某个 fact，是纯计算；交给 LLM 只会
引入方差和成本。LLM 只负责它擅长的部分：一段文字是否支撑一句话。

## 后果

- 数字型答案的引用分不再依赖"恰好引到含数字的段落"，而是直接可复算；
- prompt 变长了一点（两种句柄），但 trace 里能清楚看到模型用了哪种；
- 旧的 W2 答案没有 `facts` 字段，回放时按"无 fact 引用"处理，不能与新结果混算引用率。
