# 从 56% 到 95%：财报 Agent 的引用校验是怎么做对的

> 这是一篇写给做 RAG / Agent 工程的人看的复盘。所有数字都来自仓库里的评测报告，复现命令在文末。
> 项目：FinTrace，一个可审计的美股财报研究 Agent。

## 一、先说结论

我们最初以为"引用"是个前端问题：回答后面挂几个链接，点开能看到原文，就够了。

做完才发现不是。**"有引用"和"有证据"是两件事。**

W2 结束时，我们的引用支撑率是 **92%**——按结构口径：引用指向的段落真实存在、引文和原文相似、引用来自本次检索结果。看起来很好。

但同一批答案，用 claim 级语义校验重新判，只有 **56.1%** 的引用真正支撑了它所在的那句话。

中间那 36 个百分点，就是"引了，但没支撑"的部分：引用了一段相关但不够具体的段落；用 Item 7 的定性讨论支撑一个只有 Item 8 才有的数字；或者引用一句话，却把"可能"写成了"将会"。

到 W3 结束时，语义支撑率做到 **95–96.4%**。下面是我们做对的三件事，以及一件没做好的事。

## 二、第一件事：让引用变成选择题，不是填空题

最早的 prompt 让模型自己写引用，格式是 `(accession, item, char_start, char_end)`。

结果可以预料：它会编。不是恶意地编，而是模型没有能力记住 accession 数字，于是写出看起来很像的字符串。

后来改成**句柄制**：

- 检索工具返回的每一段证据，带一个句柄 `[K1]`、`[K2]`……；
- XBRL 数字带 `[F1]`、`[F2]`……；
- 模型只能引用"本次工具返回过的句柄"，不能在答案里自己拼 accession。

这一改，引用从"填空题"变成了"选择题"。模型不需要记住任何 ID，只需要说"我用了第 3 条证据"。运行时再把句柄映射成真实的 `(accession, item, char_start, char_end)`。

它带来的直接好处是：**引用一定指向真实存在的片段**。模型可以选错，但不能编造一个不存在的出处。结构上的可信度，在这一层就锁死了。

## 三、第二件事：结构校验和语义校验分开

有了句柄之后，校验分两层。

**结构层（确定性，0 成本）**：

1. 句柄存在；
2. 句柄指向的 section 真实存在；
3. 引用区间落在 section 内；
4. 引文和原文相似度 ≥ 0.9；
5. 句柄出现在本轮 evidence 里（防止模型引用没看过的内容）。

**语义层（LLM，按 claim 判）**：

对每个带 `[Kn]` 的句子，把它和引用的原文一起交给判官，判 `supported / partial / unsupported`。指标是 `supported claims / cited claims`。

两个设计细节值得说：

- **分母按题取均值，不按 claim 总数**。否则一个长篇回答会稀释掉短回答里的错误。
- **没有引用的可答题记 0**。这一条是为了堵"少写就不扣分"的作弊路径——如果只统计带引用的句子，模型可以通过少写句子把比例刷上去。

## 四、第三件事：数字的引用和文本的引用分开

财报场景里，数字和叙述是两个问题。

我们的做法是：**数字不经过 LLM**。所有财务数字来自 SEC 的 XBRL 结构化数据，模型只负责"选哪个事实、怎么措辞"。数字的出处是 `[F#]`，指向一个具体 fact（tag、期间、单位、值）。

文本的出处是 `[K#]`，指向一段原文。

分开之后，校验规则也分开：

- 数字：拿答案里的数字和 `[F#]` 的 fact 值做相对误差比对（容差 0.5%）；
- 文本：走 claim 级语义校验。

这看起来只是工程洁癖，实际是让"数字错"和"引用假"变成两类可独立度量的失败，而不是混在一起的一团。

## 五、判官凭什么可信：60 条盲标

LLM 判官最大的问题是没人验证它。我们做了三件事：

1. **盲标**：导出 60 条答案，隐藏机器分，人工先独立打 0/1/2；人工标完才看机器结果。
2. **只改 rubric，不改人标**：初版 κ = 0.603，方向性偏差很清楚——判官偏宽（6 条人判 1 分、机判 2 分）。我们只改规则（2 分必须覆盖全部 key_points；只有计算题要过程；时点/注入题必须表态），人标一行没动，κ 升到 **0.795**，完全一致率 90%。
3. **不接受"完美"**：剩下 6 条分歧里 3 条是题目措辞歧义。继续针对这 6 条调 prompt 就是在 60 条样本上过拟合，所以停手，并在报告头固定写 `judge_kappa=0.795`。

引用校验器另做了 30 条 claim 盲标：一致率 86.7%，加权 κ = **0.634**。4 处分歧全部落在 `partial` 这个中间档——复合句被放宽成 supported，来源说明被判 unsupported。

**κ = 0.634 的含义是：引用分的相对趋势可信，单题绝对值不要当精确测量。** 这句话我们写进了报告，而不是藏起来。

## 六、没做好的那件事：指标曾经虚高

W2 的 92% 结构分是个教训。它不是假数字，但它回答的是"引用格式对不对"，不是"引用对不对"。

我们后来在报告里把两个数并列：

> W2 结构支撑 92% → W3 语义支撑 78%（同一批答案）。

结构分虚高的部分，就是"引了但没支撑"。这句话后来成了整个项目最好用的一个自我提醒：**任何指标都要问一句，它到底在量什么。**

## 七、复现

```bash
git clone https://github.com/evinyang-zw/fintrace
cd fintrace
make up && make ingest && make embed      # 首次约 15 分钟
make eval AGENT=graph JUDGE=llm           # 70 题终版评测
```

- 评测口径：`docs/metrics.md`
- 终版报告：`docs/evaluation-report.md`
- 引用校验器：`eval/citation.py`
- 判官校准：`scripts/annotation_pack.py` + `scripts/kappa.py`

如果只能从这篇拿走一句话：**先定义"什么叫引用对"，再让模型去引用。**
