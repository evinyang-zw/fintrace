## 1. 掘金首发

**为什么先发掘金**：原生 Markdown、技术读者密度高、搜索长尾好、代码块和表格不会乱。

### 1.1 发布前

- [ ] 注册/登录掘金，绑定手机号（创作中心 → 写文章）
- [ ] 头像与简介：建议一句话定位 ——「把不确定的 LLM 系统做成可测量、可复现、可运维的工程系统」
- [ ] 打开两篇 Markdown，确认代码块与表格渲染正常

### 1.2 发布步骤

1. 「写文章」→ 标题：直接抄文章一级标题。
2. 正文：把整篇 Markdown 粘贴进编辑器（掘金支持 Markdown 粘贴；如果被转成富文本，点编辑器右上角切 Markdown 模式再粘）。
3. 分类：**人工智能**。
4. 标签（最多 5 个）：文章 A → `AI Agent`、`RAG`、`大语言模型`、`LLM`、`评测`；文章 B → `AI Agent`、`大模型评测`、`LLM`、`方法论`、`工程实践`。
5. 封面：上传对应 `covers/*.png`。
6. 摘要（100 字内，直接复制）：
   - A：`同一个 92% 的引用指标，换成语义口径只剩 56.1%。这篇拆三层校验：句柄制、结构校验、claim 级 entailment，以及判官 60 条盲标 κ 0.603→0.795 的校准过程。`
   - B：`设计文档写 100 题，我最后停在 70。这篇算清楚扩题的时间账，讲 holdout 纪律怎么执行、第一次 holdout 怎么抓出判分器 bug，以及为什么"少而能解释"比"多而注水"更难。`
7. 勾选**原创**；不开付费；不挂公众号/二维码。
8. 预览：重点检查 4 处——表格、代码块语言高亮、外链、行内 `code`。
9. 发布，等审核通过（通常几分钟到几小时）。

### 1.3 发布后的第一件事

把文章 URL 记下来，回填：
- README 里「两篇文章」那一行（替换 `docs/articles/` 链接）
- `w6-report.md` 的交付物表（把"初稿/待发布"改成链接）

## 2. 知乎二发（1–2 天后）

**为什么二发**：知乎长文流量大、适合"方法论"这篇；但掘金先发能拿到首发推荐。

1. 创作中心 → 写文章。
2. 知乎编辑器对 Markdown 支持不稳定：**不要直接粘 Markdown**。推荐：
   - 打开掘金已发布的文章页 → 全选复制（富文本）→ 粘进知乎；或
   - 用 Typora/VS Code 预览 Markdown → 复制渲染结果 → 粘进知乎。
3. 逐项检查：表格是否错位、代码块是否丢缩进、链接是否可点。
4. 话题：`人工智能`、`大语言模型`、`Agent`、`RAG`。
5. 文末加一行：`本文首发于掘金：<链接>`。
6. 封面可不上传（知乎会自动抓取首图；我们的文章没有图，建议手动上传同一张封面）。

## 5. 不要做的事

- 不要放二维码、公众号、微信群（掘金会限流甚至删文）。
- 不要标题党夸大：写 99% 必须带"60 题开发集"的口径，否则评论区会揪。
- 不要在正文里"求内推"超过一句；作品本身是主菜。
- 不要同一天两平台群发，也不要在多个平台互相 claims 首发。
- 不要把 Demo 口令写进公开文章（现在没有公开 token）。
