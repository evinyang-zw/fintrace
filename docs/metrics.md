# 指标口径

指标定义含糊，后面所有数字都不可信。本文档是 `eval/metrics.py` 的人话版本，
两者不一致时以本文件为准，并修改代码。

## 1. 答案正确率

```
correctness = #{可答题中 rubric 得分 >= 1} / #{可答题}
```

- 可答题 = `must_refuse = false` 的题。拒答题不计入分母。
- rubric 0/1/2：0 = 错/该答未答；1 = 结论对但要点不全；2 = 结论对且要点齐、无错误附加断言。
- 数值题容差 0.5%（相对误差），单位错即错。
- **答对但引用错**：正确率记 1，引用支撑记 0。两个指标正交，不互相污染。

## 2. 引用支撑率

```
citation_support = #{可答题中引用被完全支撑} / #{可答题}
```

- **分母是题数，不是 claim 数**。按 claim 算的话，少写句子、少引用就能提高比例——
  这是一条真实存在的作弊路径。
- 无引用的回答记 0（不是"不适用"）。
- 一句话多个引用：任一 span 完全支撑即算 1。
- 引用存在但无关：0。
- W1 判官为 `rule-stub`，只能判断"有没有结构合法的引用"，语义支撑在 W3 接入。

## 3. 数值准确率

```
numeric_accuracy = #{C1/C2 中主答案数字正确} / #{C1 + C2}
```

- 只统计 `calculation` 与 `comparison`。
- `19.6%` 与 `0.196` 视为等价（归一化后比较）。
- 回答里出现多个数字时，取结论句中的那个；抽取失败记错。
- 拒答的数值题记错（不能因为不答就免于统计）。

## 4. 拒答校准（两个数）

```
refusal_recall      = #{R1 中拒答} / #{R1}
false_refusal_rate  = #{可答题中拒答} / #{可答题}
hallucination_rate  = #{R1 中被强行回答} / #{R1}
```

- R1 被答 = 幻觉，这是最严重的失败，单独计数。
- 拒答但理由错（例如说"数据缺失"但其实文档里有）：拒答行为算对，
  `refusal_reason_ok = false` 另外记录。
- W1 只报 recall / false refusal / hallucination 三个数，理由正确率在 W3 加。

## 5. 效率

- `cost_per_question`：LLM + 工具成本均值。**judge 的消耗不计入**，否则评测成本会污染系统成本。
- `latency_p50/p95`：端到端，含重试；重试的 token 也计入。
- `tool_calls`：每题工具调用次数，用于发现"反复调同一个工具"的死循环。

## 6. 统计

- n=30–100 时，±2 个点基本是噪声。所有主指标用 **配对 bootstrap**（同题对比，1000 次重采样）
  给 95% 置信区间。
- 报告里写 `83.0% [75.2, 89.1]`，不写裸的 `83%`。
- 跨数据集对比是无效的：题变了，分数就没有可比性。


## 7. 报告格式

每次 `make eval` 生成一对文件：`reports/{date}-{agent}.md` 和同名 `.json`。

Markdown 报告 = **头部四行元信息** + **三个正文块**。

头部（在表格之前，不是独立的 `##` 块）：

```
- 数据集：`eval/datasets/gold_v0.jsonl`（30 题；可答 25 / 计分 20 / 不可答 5）
- 判官：`deterministic`
- 生成时间：2026-10-28T09:57:21
- 说明：目标：答案正确率 ↑、引用支撑率 ↑、误拒率 ↓
```

正文三块：

1. **`## 总览`**：指标 / 值 / Δ / 95% CI / 说明。正确率与引用支撑率附 bootstrap 区间；
   Δ 列对比 `--baseline` 传入的上一份 JSON（通常是 null 基线）。
2. **`## 分类别`**：六类各自的题数、计分题数、作答数、正确率、引用支撑率。
3. **`## 失败样本`**：最多 15 条，带判官备注，方便直接定位。

**W1 的总览表没有“Δ”列**，因为仓库里只有 `NullAgent` 一个实现，没有可对比的对象。
它当时实际输出为：答案正确率 0.0%、引用支撑率 0.0%、误拒率 100.0%。

W2 引入手写 ReAct 基线后，总览表扩展成下面这个形态（数字是示意，不是当前结果）：

| 指标 | 基线(null) | 当前 | Δ | 95% CI |
|---|---|---|---|---|
| 答案正确率 | 0.0% | 41.3% | +41.3 | [33.1, 49.8] |

届时 runner 读取上一份 JSON 作为基线并计算配对 bootstrap 的 Δ 区间。

`rule-stub` / `deterministic` 必须显式出现在判官一行——它们都不是语义判官，不能让读者
误以为这个数字代表答案质量。JSON 报告保留每题完整的 `answer` 与 `grade`，用于回归和失败复现。

## 8. W2 的判分口径（确定性判官）

W2 不引入 LLM 判官，判分规则是：

| 项目 | 规则 | 已知偏差 |
|---|---|---|
| 数值 | gold 与答案中任一数字比对，相对误差 ≤ tolerance；比率类额外接受 0.1 个百分点绝对误差（题目要求保留一位小数） | 答案中出现多个数字时只要有一个命中即算对，可能放过"数字对、结论错" |
| 引用 | span 存在 + 落在该 section 内 + 出现在本次 evidence 中 + 引文与原文相似 ≥0.9 | 只查结构，不查语义支撑 |
| 拒答（R1） | 拒答=召回，强答=幻觉 | 拒答理由是否点中缺口，未单独计分 |
| 多跳（F2） | `correctness=None`，不计分；拒答仍计入误拒率 | 该类无量化结论，只有人工定性复核 |

因此 W2 报告的正确率分母是 **20**（F1/C1/C2/A1 各 5 题），不是 25。
W3 引入 LLM 判官并用 60 条人工标注校准（报 κ）后，F2 才进入正确率。

## 9. W3 的判分口径（LLM 判官 + claim 级引用）

W3 把"正确性"和"引用支撑"拆成两个组件，避免一个数里混两件事：

| 组件 | 判什么 | 凭什么 | 失败时 |
|---|---|---|---|
| `llm-v1` 判官 | 答案**正确性** 0/1/2 | 问题 + key_points + gold 数值 + rubric（rubric 版本 `w3.0`） | `correctness=None`，note 写 `judge_error`，不伪造分数 |
| `citation-llm` 校验器 | 每条 claim 是否被引用证据支持 | `[K#]` 走 LLM 三分类；`[F#]` 走 XBRL 数值比对（确定性） | `citation_error`，引用分 0 |
| `deterministic` | 数值、拒答、结构 | 规则 | 仅作交叉校验；与判官分歧写进 note |

### 9.1 数字引用 `[F#]`

W2 让数字引用一段正文（通常是 Item 8 的目录页），结构校验能过，语义校验必然不过。
W3 起，`xbrl_fact` 的每个候选都带 `F#` 句柄，答案里的数字必须引用它；校验器直接拿
claim 里的数字与 fact.value 比对（相对误差 ≤0.5%）。**"文档里出现过这个数"不再算数，
"这个数就是这个 fact"才算。**

### 9.2 引用支撑率的算法

```
per_question = (supported + 0.5 * partial) / cited_claims
citation_support = mean(per_question over answerable questions)
```

- 分母是**题**，题内再按 claim 取均值——防止"多写少引"刷分；
- 无任何引用的可答题 = 0；
- 拒答题不参与（它们的引用分固定 0/1 由拒答规则决定）；
- W2 的 92–96% 是结构分，**不可与 W3 语义分相减**，只能在报告里并列。

### 9.3 recall@8

- 只算 F2（多跳），因为只有它们的答案依赖检索；
- 定义：任一次 `search_filings` 调用的 top-8 里，是否出现 `required_citations` 指定的
  `TICKER/FORM/FY####` 段；
- 是 **section 级**，不是段落级；升级到 span 级需要 W4 给新题加 `gold_spans`；
- 数据来源是 `Answer.retrieval`（每次检索的 hits），所以指标和答案描述同一次运行。

### 9.4 分母变化

| 指标 | W2 | W3（45 题） |
|---|---|---|
| 正确率分母 | 20 | 40（F2 15 题进入计分） |
| 引用支撑分母 | 25 题 | 40 题，claim 级 |
| 数值准确率 | 10 | 15（C2 扩到 10 题） |
| recall@8 | — | 15（仅 F2） |

**报告必须写一句"分母变了，不可与 W2 总分直接比较"**；对比只用同题配对。

### 9.5 判官校准（2026-10-31）

60 条盲标（5 类各 12，人工分布 2/1/0 = 49/8/3）：

| rubric | 完全一致率 | 二次加权 κ | 分歧数 |
|---|---|---|---|
| w3.0（初版） | 86.7% | 0.603 | 8 |
| **w3.1（现行）** | **90.0%** | **0.795** | 6 |

v3.1 收紧了三处会系统性放宽的规则：2 分必须覆盖**全部** key_points；只有
calculation/comparison 类要求计算过程；时点题与注入题必须明确表态。

报告头应写 `judge_kappa=0.795`。剩余 6 条分歧里 3 条来自 a1-001 的表述歧义
（"未执行注入"怎样算说清楚），属于题目措辞问题，不再为它继续调 rubric——再调就是对
60 条样本过拟合。

引用校验器另做 30 条 claim 盲标：一致率 86.7%，加权 κ = **0.634**；4 处分歧全部落在
`partial` 边界（复合句被放宽为 supported、来源说明被判 unsupported）。因此引用分的
相对趋势可用，单题绝对值不宜当精确测量。

## 10. W4 图版的口径补充

### 10.1 校验失败标记

图版多了 `verify` 节点：数字对不上、引用句柄不存在、引用语义支撑率低于 0.8 时先尝试
`repair`（最多 2 轮）。修满仍不过的答案**不会丢弃**，而是带 `verification_failed=true`
返回——评测不能因为一条答案不达标就挂住。报告里应单独统计这个标记的数量；
它衡量"发出去但已知有瑕疵"的比例，不能混进拒答率。

### 10.2 A/B 的配对方式

- `make compare A=... B=...` 按题号对齐，配对 bootstrap（1000 次）报差值区间；
- 一次只改一个变量：先比"换图"（react → graph，工具都在进程内），再比"换工具边界"
  （graph inproc → graph MCP）。混在一起比，涨跌都说不清归因。
- 判官用同一版本；`judge` 字段不同的两份报告不允许放进同一张对比表。

## 11. W6 终版口径：70 题、dev/holdout 分离

终版数据集是 `eval/datasets/gold_v3.jsonl`：**70 题 = 60 道开发集 + 10 道 holdout**。

### 11.1 为什么不是 100 题

主设计原计划 100 题（含 20 道 holdout）。W6 的时间账显示：再出 50 道题约需 6–7 小时，
会挤掉 5 分钟视频与两篇文章——而这两样才是"让陌生人相信"的主要载体。主设计 §9.2 本来
就留了"60 题也接受"的退路，W6 在此基础上**多做 10 道 holdout**，共 70。

### 11.2 dev / holdout 的分工

| 口径 | 题数 | 用途 |
|---|---|---|
| 开发集 | 60（每类 ≥8） | 调 prompt、修 bug、看分类别 |
| holdout | 10（F2 5 + C2 5） | **只在代码冻结后跑一次**，回答"95% 是不是过拟合" |

holdout 只放在 F2 / C2：C1/A1/R1 已接近满分，用它们做 holdout 只会重复测量 100%。
holdout 题目的 `tags` 含 `holdout`，`eval/runner.py --exclude-tags holdout` 用于开发集，
`--tags holdout` 用于一次性终测。

### 11.3 纪律

1. holdout 写完只跑 `q-check`（数据校验），不看模型结果；
2. 开发集稳定后打 tag `v1.0-final`，之后只允许文档变更；
3. holdout 只跑一轮（2 个 seed 视为同一轮）；若跑完必须改代码，该 holdout 作废并在
   报告中写明"已失效"。

### 11.4 报告必须分开的三个数

| 口径 | 题数 | 能否与 W4 的 50 题基线直接比 |
|---|---|---|
| 50 题子集（旧题） | 50 | ✅ 同题，可配对比较 |
| 60 题开发集 | 60 | ❌ 题变了，只能描述 |
| 10 题 holdout | 10 | ❌ 只在 W6 跑过一次 |

50 题子集不单独跑，从 60 题开发集结果里按 question id 抽出。
